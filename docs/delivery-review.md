# 媒体生成与交付核验

## 这次实际发生了什么

生产记录显示，“重新做一遍”及其后的数次“正在生成／已发送”回复没有新的 `generate_image` 调用或媒体子任务。早先的 `task_status` 返回了一张旧图片的成功状态，助手把它当作后续请求的结果。直接 `/image` 创建的任务则有独立的图片任务和输出文件。

此前仅保存 `delivered=1`，没有 Telegram 消息 ID。旧标记表示旧代码走完了发送或跳过分支，不能追溯证明某张图在某个聊天里被平台接受，更不能证明用户已看到。

## 对照的上游设计

- [OpenClaw 消息生命周期](https://docs.openclaw.ai/concepts/messages)：代理运行与出站交付分开；工具正文与交付元数据用途不同。
- [OpenClaw Channel outbound API](https://docs.openclaw.ai/plugins/sdk-channel-outbound)：运行时拥有队列、持久化、重试和回执；平台适配层负责真实发送，并返回可见回复状态和平台消息 ID。
- [Hermes 平台基类](https://github.com/NousResearch/hermes-agent/blob/main/gateway/platforms/base.py)：媒体通过平台发送接口处理，`SendResult` 的成功／失败进入交付记录；失败路径有重试或通知，不能只从助手文本推断成功。

这里只借鉴可验证的交付分层，没有迁移到这些框架，也没有声称它们能完全避免模型幻觉。

## 当前实现

1. **请求关联**：媒体任务保存 `parent_job_id`；旧记录只从真实成功工具调用恢复关联。旧图不自动归属于新请求。
2. **状态证据**：区分任务提交、任务运行、本地有效文件、平台接受回执。`task_status` 返回当前用户和会话内的证据；不拿聊天任务的成功当作媒体成功。
3. **交付回执**：`delivery_receipts` 保存 job、消息片段、目标 chat、平台 message ID 和时间。文字片段、语音、媒体和失败通知分开记账。已有回执的片段不再次发送。
4. **交付失败**：记录错误类型、尝试次数和重试时间。文件丢失或累计三次失败后尝试发送简短失败通知，通知本身有独立回执，不计作媒体发送成功。
5. **出站回复校验**：媒体提交确认由运行时按关联任务状态生成。无依据的常见声明触发最多两次纠正回合；允许查询状态、分页列出媒体，以及完成用户明确要求的发送。清单不能当作发送完成，发送结果按本轮逐文件回执汇总，部分失败单独说明。
6. **投诉自查**：删除投诉关键词直接返回固定文案的捷径。此类消息仍交给 Qwen 理解和调用工具。
7. **历史处理**：历史记录原文保留；重新发给模型时排除媒体完成声明，避免重复错误回复。每轮附带新鲜的交付证据。

所有内部检查只写入本机审计记录，Telegram 不展示执行步骤。正常收到消息的 reaction 和 typing 保留。

## 验证与边界

2026-09-26：54 项测试通过，包含旧图误关联、未提交却宣称生成、缺文件、发送失败、缺回执、分段幂等、用户隔离以及复核阶段副作用拦截。

本地端到端实测使用普通橘猫请求：真实 Qwen 调用生成工具，真实图像引擎产生 smoke PNG；发送适配器模拟返回 Telegram 消息 ID 后，关联和回执正确持久化。该测试没有向用户 Telegram 发送测试消息，不能描述为真实 Telegram 收件验证。报告在 `runtime/evidence-test/report.json`。

文本声明识别是针对常见中文／英文表述的防线，不是通用语义证明器。旧记录没有消息 ID，不伪造补填；Telegram 接受回执也不是已读回执。网络发送成功后、回执落盘前崩溃仍存在重复发送窗口。图像编辑与自动重新生成未在本次修复中扩展。


## 历史媒体交付升级

- `list_media` 只查询当前用户、当前对话在本轮开始前完成的媒体，默认图片；每页 50 项，返回总记录数和下一页位置。不存在的文件也明确标记，不能算成功交付。
- `send_media` 接受查询得到的媒体 ID，每批最多 50 个，重新校验所有权、文件和授权，通过与正常交付相同的 Telegram Bot 通道发送。收件人固定为当前聊天，不接受模型指定路径或任意收件人。
- 每个回执保存在当前请求的 `artifact:<原媒体ID>` 下。同一轮已收到回执的文件不会重复发送；用户下一轮明确要求再发时允许重新发送。状态查询包含后续重发回执。
- 明确要求发送或“图呢”等索要媒体的追问可使用发送工具；询问是否已发送或明确说不要发送时拒绝。这个中英文常见表述检测仍有覆盖范围限制，不是完整语义授权系统。
- 复核阶段只开放状态、媒体查询和发送，避免为补救错误声明创建新生成任务。模型仍有单轮 10 次工具调用、8 次推理预算；大批量超出预算时可能只完成部分，并明确说明剩余文件。
- 发送超时可能发生在平台接受后；无有效消息 ID 时只报告失败，不能保证跨网络故障的严格一次交付。失败重试依靠本轮模型继续执行或用户新请求，没有新增无限后台重发。

本次回归测试覆盖分页、7 张图片与视频混合记录、部分失败、重试去重、不同用户和聊天隔离、缺文件、缺回执、撤销授权、取消、否定发送请求，以及复核后实际继续发送。真实 Qwen 测试报告位于 `runtime/artifact-test/report.json`，Telegram 传输使用测试替身，不会把历史媒体自动补发给用户。

复核发现索要媒体却未查询或发送时，下一次模型调用通过 `tool_choice` 指定缺失步骤的工具，参数仍由 Qwen 根据请求和查询结果提供。成功标准为实际逐文件回执，不是模型回复的措辞。

本次升级回归套件：64 项测试通过。本地推理服务的工具选择使用字符串 `required` 加单个工具声明；该服务不接受 OpenAI 风格的具名对象格式，不能依赖被忽略的参数约束执行。
