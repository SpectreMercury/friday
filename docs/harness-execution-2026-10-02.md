本次范围是任务拆分、工具调用、错误恢复与完成判断；视频重复是暴露问题的一个场景。自动测试通过不能替代真实模型执行，更不能替代视频内容验收。

以下实现是对本项目的适配，不是声称复制了 Codex 的内部实现，也没有把 DeepSeek 整个运行时接入生产。

## 已复现的问题

1. 生产日志有多轮任务单次调用 `continue_task` 22–23 次。关联动作占满预算，实际目标没有推进。最近十二个聊天任务未保存工作计划，复杂工作没有持续更新的步骤状态。
2. 真实 Qwen 隔离验收中，两项 `calculate` 均正确返回 `0.3` 和 `false`，最终正文正确、各项检查均满足，但合同和核验把同一要求分为不同证据类别，宿主最终判为 `partial`。原始失败记录保存在 `runtime/harness-media-acceptance/1790940934837526000/`。
3. 审批等待既可能被算成缺少资料，也可能被算成不可用结果。成功媒体任务又会保留审批恢复时的 `pending`。
4. 重复失败直接结束整体任务，缺少在同一目标下转用其他方法的阶段；核验重试会重新开放整套工具，包括已经完成的关联动作。
5. 历史三个视频项目含重复提示词；不同随机种子产生不同文件，不代表剧情不同。最新四镜头文件及合并顺序正常，但这不能证明语义或画面质量。
6. 视频裁切缓存只比时长；原片改变后可能复用旧片段。PWA 播放器未按产物版本更新。
7. 主进程输出的是可能截断的任务视图包装，Node 却按完整原始对象读取关联与计划状态。初始化之外，运行中关联旧任务也没有刷新未完成计划状态。
8. 第二次真实计算验收仍失败：成功只读调用被排除在 operation 证据之外，核验要求重算，最终把正确答案替换成失败通知。原始记录保存在 `runtime/harness-media-acceptance/1790941468576252000/`。
9. 输出预算与超时不匹配：本地实测约 15.8 token/s，而 4096 token 的核验仅给 90 秒。合法生成可能被截断，随后触发重试与模型重载。

## 执行协议

- 简单问答和一步操作直接执行。复杂工作使用同一个 `plan_task` 的 `work_items` 完整快照；步骤包含稳定编号、描述、状态，并可附依赖、完成条件、真实证据编号。宿主检查编号、依赖存在和无环；返回当前步骤、可开始步骤和仍等待前置条件的步骤。独立后台工作可以同时进行。
- 计划是方法和进度，不是权限或完成证明。原始用户输入独立保存；计划不能覆盖它。现有字符串步骤及旧内部快照继续可读，旧任务不会被强制重写。
- 已由宿主关联的任务立即关闭重复关联入口。发现过的工具集合在继续、核验修复和用户补充之后保留。
- `execution_state` 单独传递宿主控制状态，不读取模型视图推断控制信息。初始化、关联任务、更新计划之后都同步；完整与截断任务视图均通过实际 Python → Node 集成测试。
- 计划可能漏掉最后一次更新。最新计划的来源执行已同时 `succeeded + completed` 时，不因残留 pending 步骤重开旧任务；其他状态继续保留未完成工作。来源查询限制在同一任务、账号和会话。
- 同工具、同参数的失败路径耗尽后，最多进行两次有界恢复；仍可使用其他方法完成剩余步骤。封禁的失败路径、恢复次数与总预算随检查点保存。无关成功结果不会重新开放耗尽路径；真实新用户输入可以重置路径判断。
- 重复查询时，如果工作清单仍有未完成步骤，则进入上述恢复流程；只有无剩余执行计划的普通纠正直接回应。不会把内部轮次、运行中状态或重试限额当作用户缺失信息。
- 结果核验使用当前要求实际引用的、完整、同范围的真实证据。只有同时支持两类证明的同一份已核实证据，才能消除两轮模型分类差异；文字说明不能替代外部观测、写入、文件或送达回执。
- 证据协议 v6 区分 `operation`（工具实际被调用）和 `effect`（实际副作用）。只读调用可以证明调用发生，不能证明保存或预约；v5 合同中的 operation 保守沿用旧的副作用含义。旧缓存按协议版本失效重建。
- 原始第二次失败的最初两条真实回执已在只读重建中通过 v6 归一化；数据库与报告哈希保持不变。这是对保存结果的重放，不冒充新一轮模型执行。
- 合同、核验、普通模型调用的上界分别调整为 180、300、240 秒，与本地输出速度匹配；主进程总上界为 1800 秒。工作预算 360 秒、48 次工具调用、24 轮、3 次核验、2 次恢复均未增加。总上界可能先于全部可选重试耗尽，不能把它理解为每次重试都保证执行。
- 审批等待由实际记录推导为 `needs_input`。成功媒体执行结束后记录 `completed`；聊天仍可保持真实的 `pending`、`partial` 或 `blocked`。

## 视频与播放

新分镜明确初始状态、主要动作和结束状态，并核对这些内容进入实际渲染提示词；重复动作与结果在渲染前要求修订。此检查只能保证结构和文字约束，不是语义或视觉模型。已确认的旧分镜保持原版本。

裁切缓存同时核对原片及导出文件内容指纹。PWA 收到新产物版本时释放旧播放器；同版本刷新保留播放进度。原生 iPhone 播放器的同任务换版本行为未在本次改动中发布。
