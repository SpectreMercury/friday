# H3 单路 / 双进程 GPU 并发压力验证 · 2026-09-28

## 结论

生产继续保持1路GPU生成。两个独立Comfy进程均成功加载H3并进入采样，但约47秒后触发预设swap保护，未产出双路完整结果。本次不能证明双路物理上无法完成，也没有测出双路端到端吞吐、加速比或理论最大并发。

## 实验设置

设备：Mac17,16，64GiB统一内存。使用与生产相同的H3量化模型、LoRA、352×608分辨率、362帧（24fps约15.08秒）和采样算法；本轮将8步改为2步，先检验压力与趋势，不用于画质或正式生成耗时评估。单路seed7100；双路分别7100/7101，提示词相同，均从新进程开始。

先跑一个完整单路样本并结束进程，再同时启动两个独立进程、几乎同时提交任务。双路使用8289/8290两个本机端口；没有把Comfy单进程排队误算成GPU并发，也没有删除生产GPU锁。

运行期间通过现有短期admission drain暂缓新推理，保留App/API访问。脚本每5秒续租，结束释放，脚本意外退出后租约120秒过期。测试前检查无在途任务、实时语音或升级；首次重启仅为释放生产常驻模型。专用engine文件锁防止另一个引擎占用。测试完成已确认drain为0、健康检查通过、测试进程退出。

## 观测

| 指标 | 单路 | 双路 |
| --- | ---: | ---: |
| 任务结果 | 成功，视频及音轨可解析 | 两进程进入采样，保护停止，无成片 |
| 提交至结束 | 426.31秒（7分6秒） | 46.86秒时停止 |
| 采样耗时 | 两步285.26秒，约142.63秒/步 | 未完成首步，无有效步速 |
| 系统swap最大观测值 | 0.981GiB | 12.084GiB |
| 可用内存最小观测值 | 7.242GiB | 8.931GiB |
| 设备GPU利用率中位数 | 99% | 93%（主要覆盖加载及采样起始） |

GPU百分比来自IORegistry AGXAccelerator，是设备整体值，不是模型独占值；每10秒采样。内存使用psutil每5秒采样，可能遗漏更高峰值。单路采样期间GPU中位数同为99%。单路输出经ffprobe验证15.083333秒、352×608、含音视频轨；未对2步测试片做画质验收或将其当作正常作品发送。

双路的预设swap阈值为单路最大值+8GiB（约8.98GiB）；一次采样观测达到12.084GiB后终止两个进程。另有可用内存低于2GiB持续20秒的停止条件，本次未触发。这里是主动保护，不是系统OOM，也不是已经证明会崩溃。系统保留可用内存的同时会增加swap，因此不能仅凭free/available判断双路是否健康。

## 影响与下一步

单路已持续充分利用GPU；当前双进程会重复加载编码器、模型及运行态，尚未通过内存保护要求。不能据此缩短之前24小时容量估算，也不能将预备窗口2改称2路渲染。

本次未测试共享权重的批处理、不同模型混跑、图像或聊天并发。现有H3节点未暴露batch_size，AV latent使用NestedTensor，不能直接把普通RepeatLatentBatch当成已支持的视频批处理。若继续研究，应先做共享权重/内存调度适配，再对相同8步配置完整比较两段顺序与并发的总时间。
