# Friday 原生聊天组件库

实现：[FRChatComponents.h](Sources/FRChatComponents.h)、[FRChatComponents.m](Sources/FRChatComponents.m)。生产聊天页直接使用这些组件；组件不发网络请求、不保存凭据、不自行批准操作。

| 组件 | 用途 | 状态与交互 |
| --- | --- | --- |
| FRPermissionCard | 会话权限缺口、待审批操作 | 图标、说明、查看按钮；打开授权弹窗 |
| FRPermissionController | Mac 管理授权、单次操作审批 | 可滚动的完整说明；允许、拒绝、稍后处理；提交锁定；失败原位重试 |
| FROperationCard | 任务操作、补充请求 | 独立按钮区，支持继续编辑和停止任务 |
| FRStatusCard | 项目/镜头进度、操作错误 | 明确的状态标题与说明 |
| FRImageCard | 图片 | 受约束的等比预览、打开原图、文件名、加载与重试 |
| FRVideoCard | 视频 | 原生 AVPlayer 预览区、打开文件、加载与重试 |
| FRAudioCard | 音频 | 原生播放器、文件名、打开文件、加载与重试 |
| FRFileCard | 其他附件 | 文件名、打开原文件、加载与重试 |
| FRSkeletonView | 列表、消息、媒体加载占位 | 遵循减弱动态效果；离屏和后台停止动画 |
| FRActionButton | 所有卡片动作 | 主操作、次操作、破坏性操作；至少 44pt 触控区域 |

卡片使用 16pt 圆角、14pt 内边距、12pt 内容间距，标题/说明/操作分别为 14/13/14pt 基准字号，随系统字号变化。垂直排列允许长文件名与按钮文案换行。普通助手正文保持可选择的文本；结构化权限缺口不再作为普通回复重复输出。

导航栏是独立的紧凑排版：标题最大 220pt，并按屏幕可用空间收窄；长会话名省略。`FRComponentSetBusy` 对旧式按钮只叠加加载指示器，不转换 UIButtonConfiguration，避免首次加载丢失原字号、边距和图片布局。

授权由聊天控制器绑定当前 session、审批 token 与账号 generation。新审批在当前聊天中弹出一次，稍后处理保留卡片入口；重复提交被禁止，审批过期/已处理不能继续提交，最终由服务端再次校验。不会扩展为目录或永久授权。Mac 管理开启后更新当前会话状态，原请求需用户检查后重新发送。

## Markdown 消息（2026-09-28）

`FRMarkdownView` 已替换原生助手消息的纯文本视图，最终回复和流式草稿共用同一个渲染入口。Foundation 层 `FRMarkdown` 负责解析，UIKit 层负责可选择文字、原生代码卡片和横向表格；不使用 WebView，不执行 HTML，不自动下载 Markdown 图片。

- 支持标题、粗体/斜体/删除线、行内代码、围栏代码块、有序/无序/缩进列表、任务勾选标记、引用、分隔线、管道表格和显式 HTTP(S) 链接。
- 代码块保留原始内容，使用等宽字体，长命令横向滚动；“复制代码”保留换行与缩进。表格列宽按实际字体计算，长表横向滚动，单元格文字仍可选择。
- “复制回复”复制原始 Markdown，覆盖跨表格、代码块和正文的全部内容。未闭合的流式围栏继续显示代码，未闭合的行内标记保留原文；未变的块保留视图，正在输出的普通段落原位更新。
- 字号变化重新排版。超过格式化预算的内容退回完整纯文本，保留复制能力。原始 HTML、远程图片、引用式链接等未实现的语法作为文字保留；这不是完整 CommonMark/GFM 引擎。来自任务产物的图片仍走独立媒体组件及原有鉴权。

## UI 2.0（2026-10-29）

设计稿：Claude Design 画布「Friday UI 2.0」（9 屏）。本节以下内容为准，覆盖上文的四标签结构。

- **导航**：三个标签「对话 / 进行中 / 作品」。原「我的」改为「Mac 与我」，从对话页左上角的 Mac 状态胶囊打开（半屏可拉满）。「进行中」的角标是进行中和等你处理的事项合计，蓝色。
- **配色**：`FRInk` / `FRPaper` / `FRSurface` / `FRHairline` 为黑白基底；`FRAccent`（蓝）只表示进行中，`FRAmber` 表示需要你处理；浅色、深色各有一组值。`FRFont` / `FRMono` 随系统字号缩放，时间和百分比用等宽数字。
- **首页（对话）**：列表上方先是"等你确认"卡片（多件时进入「进行中」），再是"正在 Mac 上进行"卡片（当前渲染的进度、排队位置和预计时间），下面是按时间分组的对话。列表改为平铺样式。
- **进行中**：顶部是 GPU 当前任务的深色卡片（打开对话 / 停止）；下面依次为需要你（审批、已暂停——点按会确认后发送"继续"）、排队（第几位、预计时间，左滑停止）、正在回复、接下来（下一个定时任务）、最近结束。
- **Mac 与我**：Mac 名称和在线状态，已加载的模型、排队数、今天完成数；下面是记忆、技能、定时任务、连接、设备、通知、外观、已归档、最近删除，以及账号。
- **审批弹窗**：琥珀色图标加标题，「拒绝 / 允许」左右并排（辅助功能字号下改为上下排列），下方是「稍后再说」。
- **后端**：新增 `GET /v1/home`（`local_ai/home.py`）。GPU 排队位置按所有账号的排队渲染计算，但只返回本人任务的详情；预计时间取同类任务最近成功运行时长的中位数（默认图片 60 秒、视频 600 秒）。旧版 Mac 服务返回 404 时，客户端退回只用任务列表。

### 删除即时生效（2026-10-30）

- 删除对话、任务记录、单轮对话、作品、短剧项目、最近删除、对话文件、定时任务和记忆时，确认后条目立刻从界面消失，删除请求在后台完成；失败时条目回到原处并提示错误。
- `FRStore.removing` 记录正在删除的 id（会话、任务、短剧所属会话），之后的刷新和 `/v1/home` 都会过滤掉这些 id，所以 Mac 还没删完时轮询也不会把条目带回来；撤销或失败时用 `unhide:` 恢复。列表页使用 `FRListController hideRows:` / `unhideRows:`，按行的 `key` 或 `id` 匹配。
- 后端：删除会话、短剧项目或单轮对话时，任务先标记为已停止并立即返回，真正停止运行中的渲染放在后台进行（`stop_later`）。
- 验证：Python 717 项（新增“停止很慢时删除也立即返回”）；删除检查 18 项（新增三项列表隐藏，以及“Mac 回复前已消失”“过期刷新不会带回”），交互 24、导航 16、组件 187 项通过。
